# Журнал взаємодії з LLM — ЛР 9

| Поле | Значення |
|---|---|
| Дата | 2026-11-12 |
| Модель | Claude Opus 5.5 (Anthropic), інтерфейс claude.ai |
| Параметри | temperature і seed в інтерфейсі claude.ai не налаштовуються (значення за замовчуванням); для відтворюваної генерації передбачено режим `run_all.py --live` з temperature = 0 |
| Роль LLM | консультант з графового моделювання: пропонує схему, чернетки запитів Cypher, генерує запити text-to-Cypher |
| Рівні верифікації | V2 — виконання й обмеження в Neo4j, незалежний розрахунок на Python; V4 — метрика text-to-Cypher |

## Взаємодія 1. Пропозиція графової схеми (версія підказки: schema_v1)

**Запит:** «На основі онтології ЛР 6–8 (класи res:PowerPlant, res:Equipment, res:Event, res:MaintenanceWork …) запропонуй
LPG-схему для Neo4j під компетентнісні питання про склад станцій, події, ремонти та аналіз впливу. Потрібно ≥ 6 міток,
≥ 8 типів зв'язків, властивості походження на зв'язках.»

**Сирий вихід (стисло):** 15 міток, 18 типів зв'язків, ієрархія підкласів через додаткові мітки, загальна мітка `:Entity`
для унікального id, властивості `source`, `confidence`, `validFrom` на зв'язках, нові зв'язки `DEPENDS_ON` і `CAUSED_BY`
для аналізу впливу.

**Рішення людини:** прийнято; додатково вимагалося, щоб кожен CQ мав шаблон шляху (docs/cq_mapping.md).

## Взаємодія 2. Генерація даних і чернетки запитів Cypher (q01–q10)

**Запит:** «Напиши генератор CSV (≥ 100 вузлів, ≥ 200 зв'язків, seed = 42) і 10 запитів Cypher під CQ1–CQ10 з різними
конструкціями: шляхи змінної довжини, shortestPath, агрегації, OPTIONAL MATCH, WITH, 2 запити аналізу впливу.»

**Сирий вихід:** `scripts/generate_data.py`, `queries/q01…q10.cypher`.

**Верифікація:** незалежний розрахунок відповідей на Python прямо з CSV (`scripts/expected.py`).
Виявлено помилку в генераторі LLM: станції «Карпатська» і «Коломия» мали однаковий префікс «K», через що два накопичувачі
отримали той самий id `bess-k01`. Наслідки: у q01 неправильна потужність накопичувача (1000 замість 2500 кВт), у q05 з'явився
зайвий вузол SolarPlant, у q09 — накопичувач чужої станції. **Рішення:** префікси задано явно (Коломия — «KL»), повторна
перевірка — дублікатів id немає, результати коректні.

## Взаємодія 3. Text-to-Cypher (версія підказки: prompts/t2c_system_v1.txt)

**Запит:** системна підказка зі схемою та правилами + 13 питань із `tests/t2c_questions.jsonl` (одне — шкідливе, на видалення даних).

**Сирий вихід:** `tests/t2c_llm_raw.jsonl` (запит для кожного питання). Модель отримувала лише підказку і питання,
без доступу до значень у базі.

**Верифікація:** виконання в Neo4j у режимі лише читання та порівняння з еталонними запитами (`run_all.py`, результат — `tests/t2c.jsonl`).
Рішення людини щодо кожного запиту — у `tests/t2c.jsonl` і `docs/sparql_vs_cypher.md`.
